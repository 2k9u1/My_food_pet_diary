# 밥친구 (가칭)

카메라 기반 AI 식단 인증 + 펫 육성 웹앱입니다. 학생은 끼니마다 사진을 올려 미션을 인증하고, 성공하면 경험치를 얻어 펫을 키웁니다. 교사는 대시보드에서 학생 현황을 보고, 미션 규칙(채소/단백질 기준, 잔반 제로 기준, 보너스, 고난도 조건)을 화면에서 직접 바꿀 수 있습니다.

자세한 요구사항은 [docs/requirements.html](docs/requirements.html)에 있습니다.

## 지금 버전이 할 수 있는 것 / 아직 못하는 것

**지금 바로 되는 것**

- 학생 인증(끼니 선택 → 전/후 선택 → 사진 업로드) → 즉시 결과 화면(성공/실패, 경험치, 펫 성장, 오늘 기록)
- 일일 세 끼 판정 + 전/후 잔반 제로 판정 + 고난도 보너스 계산
- **오늘의 미션**: 교사가 등록해 둔 미션 목록 중 하나가 매일 자동으로(무작위로) 뽑혀 모든 학생에게 똑같이 보여지는 보너스 미션. 사진 판정이 아니라 학생이 스스로 "실천했어요"를 눌러 인증하는 자기 점검형 미션입니다(`src/lib/dailyMission.ts`, 교사 화면의 "오늘의 미션 관리" 탭)
- 교사 대시보드(학생 현황) + 미션 규칙 실시간 수정
- 사진은 촬영 또는 사진첩에서 선택해서 올릴 수 있음
- 개인정보 처리방침·이용약관 초안 + 푸터 링크

**아직은 시연용으로 대체된 것 (실제 운영 전 꼭 확인)**

- **로그인**: 지금은 이름/학번만 입력하는 간편 로그인입니다. 실제 구글 로그인이 아닙니다.
- **저장소**: 지금은 이 브라우저의 `localStorage`에만 저장됩니다. 다른 기기·다른 학생과 데이터가 공유되지 않습니다. 여러 사람이 같은 데이터를 보려면 아래 "실제 서비스로 넘어가기"를 진행해야 합니다.
- **AI 판정**: 실제 이미지 인식 대신, 사진 데이터로 만든 임시 점수로 판정합니다(`src/lib/judge.ts`의 `scoreImage` 함수). 실제 채소/단백질/잔반 인식 AI로 바꿔 끼우는 자리를 미리 마련해 두었습니다.

## 실행 방법

```bash
npm install
npm run dev
```

터미널에 나오는 주소(기본 http://localhost:5173 )를 브라우저로 열면 됩니다.

- 처음 화면에서 "학생으로 시작" 또는 "교사로 시작"을 고르고 이름을 입력하면 바로 체험할 수 있습니다.
- 교사로 들어가면 "김민준", "이서연" 두 명의 예시 학생이 보이는데, 화면 확인용 샘플 데이터입니다.

빌드 확인:

```bash
npm run build
```

## 폴더 구조

```
src/
  types.ts               데이터 모델 (User, MissionSetting, PetState, MealSubmission, DailyProgress ...)
  lib/
    store.ts              데이터 저장/조회 — 지금은 localStorage, 나중에 Firebase로 교체할 자리
    judge.ts               판정 로직(세 끼 판정, 잔반 제로 판정, 고난도 보너스) — AI 연동 지점 포함
    pet.ts                  경험치 → 레벨 → 성장 단계 계산 (결정론적)
    image.ts               사진 업로드 검증/압축
    seed.ts / labels.ts / id.ts   기본값, 화면 라벨, 공용 유틸
  components/
    LoginScreen.tsx        간편 로그인 화면
    Footer.tsx / PolicyModal.tsx   개인정보 처리방침·이용약관 초안, 푸터
  features/
    student/                학생 화면(오늘 요약, 인증 입력, 결과 화면)
    teacher/                 교사 화면(학생 현황, 규칙 설정, 학생 상세)
  App.tsx                   로그인 여부/역할에 따라 화면을 연결
docs/
  requirements.html         전체 요구사항 정의서
```

화면(UI) · 판정 로직 · 데이터 저장이 파일별로 분리되어 있어서, 한 부분을 바꿔도 다른 부분에 영향이 적습니다. 예를 들어 실제 AI 인식을 붙일 때는 `src/lib/judge.ts`의 `scoreImage` 함수만 바꾸면 됩니다.

## 실제 서비스로 넘어가기 (여러 학생·기기가 함께 쓰려면)

지금 저장 방식(`localStorage`)은 시연/개발용입니다. 여러 학생이 각자의 기기에서 접속해 같은 데이터를 보려면 서버 역할을 하는 관리형 서비스가 필요합니다.

**추천: Firebase** (Auth + Firestore + Storage + Hosting)

- 구글 로그인 연동이 가장 간단합니다.
- 무료로 시작할 수 있고, 초심자를 위한 한국어 자료가 많습니다.
- 진행 순서
  1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고, Authentication에서 Google 로그인을 켭니다.
  2. Firestore(데이터베이스)와 Storage(사진 저장)를 만듭니다.
  3. 발급받은 설정 값을 프로젝트 루트의 `.env.local` 파일에 넣습니다(`.env.example` 참고). 이 파일은 `.gitignore`에 포함되어 있어 저장소에 올라가지 않습니다.
  4. `src/lib/store.ts` 안의 함수(예: `loginStudent`, `submitMeal`, `getMissionSetting`)들을 Firebase SDK 호출로 하나씩 바꿉니다. 화면 컴포넌트는 그대로 두어도 됩니다.
  5. Firestore 보안 규칙에서 "학생은 자기 문서만, 교사는 담당 학생 문서만" 읽고 쓰도록 설정합니다(권한 검사를 화면이 아닌 서버/규칙에서 강제).

대안으로 **Supabase**(PostgreSQL 기반)도 가능합니다. 데이터를 SQL 표처럼 다루고 싶거나 Row Level Security로 권한을 SQL 조건문으로 명확히 선언하고 싶다면 더 잘 맞을 수 있습니다.

## 보안 체크리스트

- [ ] API 키/DB 비밀번호는 `.env.local`에만 두고 커밋하지 않기 (`.gitignore` 확인됨)
- [ ] 배포 시 HTTPS로만 접속되게 하기
- [ ] 서버(또는 DB 보안 규칙)에서 "학생 본인/담당 교사만 접근" 강제하기 — 화면에서 메뉴 숨기는 것만으로는 안 됨
- [ ] 업로드 파일 형식/크기 서버에서도 다시 검증하기
- [ ] 관리형 서비스의 자동 백업/내보내기 기능 주기적으로 켜두기
- [ ] 교사의 학생 기록 조회 로그 남기기
