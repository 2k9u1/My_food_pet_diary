AI 실행용 프롬프트 · 요구사항 정의서 v1.1

밥친구 (가칭)

카메라 기반 AI 식단 인증과 펫 육성을 결합한 웹앱. 초등 고학년 학생이 집에서 스스로 식사를 점검하고, 교사가 미션 규칙을 직접 조정하는 구조입니다.

대상 초등 5~6학년 사용 장면 가정 · 과제 인증 로그인 구글 로그인 저장 영구 저장 · 공용 DB 역할 학생 / 교사
📸
이번 개정 반영 사항

식사 사진 제출 방식에 사진첩(갤러리)에서 선택이 추가되었습니다. 지금 바로 촬영하지 않아도, 이미 찍어둔 사진을 골라 인증할 수 있습니다. 관련 변경 지점은 문서 전체에 변경 표시로 구분해 두었습니다.

01

범위와 우선순위

이번 제작에서 완성할 범위와, 먼저 눈에 보이는 결과물로 확인할 순서입니다.

이번 범위에 포함

  • 학생 인증 화면 + 즉시 결과 화면
  • 일일 세 끼 판정 + 전/후 잔반 제로 판정
  • 고난도 미션 보너스 연계
  • 펫 경험치 · 성장 로직
  • 교사 대시보드(학생 현황)
  • 교사가 화면에서 직접 바꾸는 미션 규칙 설정

이번 범위 밖 (구조만 열어둠)

  • AI 판정 정확도 고도화(정밀 영양 분석)
  • 여러 학교 · 여러 학급 동시 운영 관리자 화면
  • 학부모 전용 화면
  • 사진 촬영 시각(EXIF) 자동 검증

위 항목은 데이터 모델과 설정 구조에 확장 여지만 남기고, 이번 구현에는 포함하지 않습니다.

  1. 1

    학생 인증 → 즉시 결과 화면

    미션 성공/실패, 경험치 상승, 펫 성장, 오늘 기록을 한 번에 보여줍니다. 가장 먼저 동작하는 것을 확인합니다.

  2. 2

    세 끼 판정 + 전/후 잔반 제로 판정 로직

    결과 화면 뒤에서 실제로 성공/실패를 가르는 규칙입니다.

  3. 3

    교사의 규칙 · 보너스 · 고난도 조건 실시간 수정

    저장하면 다음 인증부터 즉시 반영됩니다.

성공 기준 미션을 성공하면 펫이 성장하고, 성장을 위한 경험치가 오른다 — 이 두 가지가 실제로 눈에 보이면 완료로 판단합니다.

02

사용자 역할

역할로그인접근 범위주요 화면
학생 구글 로그인 본인 기록만 조회 · 제출 오늘 미션 요약, 인증 입력, 결과, 오늘 기록
교사 구글 로그인(교사로 등록된 계정) 담당 학생 전체 조회, 규칙 설정 대시보드 홈, 미션 규칙 설정, 학생 상세

역할 구분은 로그인한 구글 계정을 서버가 User.role 값과 대조해 판단합니다. 화면에서 메뉴를 숨기는 방식만으로는 권한을 막지 않습니다 (→ 10. 권한 설계).

03

핵심 기능 A — 학생 인증 및 결과 화면

1) 인증 입력 변경

학생이 입력하는 값은 세 가지뿐입니다.

① 끼니 선택

아침 / 점심 / 저녁

② 전/후 선택

식사 전 / 식사 후

③ 사진 첨부

촬영 또는 사진첩에서 선택

변경 — 사진첩 선택 지원 사진은 그 자리에서 바로 촬영하지 않아도 됩니다. 기기 사진첩(갤러리)에 있는 기존 사진을 골라 제출하는 방법도 함께 제공합니다. 학생은 두 방법 중 편한 쪽을 선택합니다.
구현 단순화 제안 모바일 웹에서는 <input type="file" accept="image/*">를 capture 속성 없이 사용하면, 브라우저가 "사진 찍기"와 "사진첩에서 선택"을 함께 제안하는 선택창을 자동으로 띄웁니다. 버튼 하나, 표준 입력 요소 하나로 이번 요구사항이 그대로 충족되어 별도의 카메라 UI를 직접 만들 필요가 없습니다.

2) 즉시 판정 및 결과 표시

업로드 즉시 다음 네 가지를 한 화면에 보여줍니다.

  • 미션 성공 / 실패
  • 경험치 상승량 (예: +15 EXP)
  • 펫 성장 상태 (레벨 · 성장 단계 변화)
  • 오늘 기록 갱신 (오늘 3끼 중 진행 상황)

판정은 그때그때 달라지지 않도록, 교사가 저장한 규칙(MissionSetting)과 고정된 계산식만으로 결정됩니다. 같은 입력이면 항상 같은 결과가 나옵니다.

3) 오늘 기록

오늘 3끼 중 완료 여부, 전/후 비교 완료 여부, 오늘 누적 경험치를 한 화면에서 확인합니다.

04

핵심 기능 B — 미션 판정 로직

🥦 일일 세 끼 미션

채소 · 단백질 섭취 여부를 판정합니다.

  • 1단계: AI 판정 점수(채소/단백질 가능성)를 교사 설정 임계값과 비교
  • 대안: 초기에는 학생이 고른 식단 태그 + 사진 업로드만으로 성공/실패 결정, 이후 AI 판정으로 확장

🍽️ 전·후 비교 (잔반 제로)

전/후 사진이 모두 제출됐을 때만 판정합니다.

  • 후(after) 사진의 잔반 정도를 적음/보통/많음으로 점수화
  • 교사가 정한 임계값 이하면 성공
  • 결과는 학생 화면과 교사 대시보드에 동시 기록

⭐ 고난도 미션 (보너스)

교사가 정한 고난도 조건 충족 시 추가 경험치를 지급합니다. 조건은 교사가 화면에서 바로 바꿀 수 있고, 저장 즉시 다음 인증부터 적용됩니다.

설정 반영 규칙 MissionSetting에는 version과 active 값을 둡니다. 교사가 저장하면 새 버전이 active로 바뀌고, 그 시점 이후 제출된 인증부터 새 규칙이 적용됩니다. 이미 판정이 끝난 과거 기록은 다시 계산하지 않습니다.

05

핵심 기능 C — 교사 대시보드

미션 규칙 · 보너스 · 고난도 조건 수정

  • 채소/단백질 판정 기준(임계값·가중치)
  • 잔반 제로 판정 기준(전/후 비교 임계값)
  • 경험치 · 보너스 지급 규칙
  • 고난도 미션 조건(추가 경험치 트리거)

저장 버튼 하나로 반영. 서버가 값의 형식과 범위를 다시 검증합니다.

학생별 현황 한눈에 보기

  • 학생 목록
  • 학생별 오늘/최근 기록 요약
  • 성공/실패 비율, 누적 경험치
  • 펫 성장 상태(가능한 범위에서)

06

화면 흐름

역할별로 화면이 이어지는 순서입니다.

학생

1
구글 로그인

학생 역할로 자동 연결됩니다.

2
오늘 미션 요약

오늘 3끼 진행 상황, 전/후 비교 진행, 누적 경험치를 확인합니다.

3
인증 시작

끼니 선택 → 전/후 선택 → 사진 첨부(촬영 또는 사진첩에서 선택)

4
결과 화면

성공/실패, 경험치·펫 성장, 오늘 기록 갱신을 즉시 표시합니다.

5
다음 미션으로 이동

버튼 한 번으로 다음 끼니 인증으로 넘어갑니다.

교사

1
구글 로그인

교사 역할로 자동 연결됩니다.

2
대시보드 홈

담당 학생 현황 요약을 확인합니다.

3
미션 규칙 설정

세 끼 기준, 잔반 제로 기준, 보너스/고난도 조건을 수정하고 저장합니다.

4
학생 기록 상세 보기

날짜별 기록, 판정 결과, 경험치 변화를 확인합니다.

07

모듈 설계

각 모듈은 독립적으로 수정할 수 있도록 역할·입력·출력·예외·주의점을 분리합니다.

① 화면/UI 모듈

역할
학생 인증 화면, 결과 화면, 오늘 기록, 교사 대시보드/설정 화면 제공
입력
사용자 선택(끼니/전후), 사진, 설정값
출력
판정 결과 UI, 기록 요약 UI
예외
설정값 로딩 실패 시 안내 문구 표시
주의
입력은 사진 업로드 + 선택 2개 수준으로 최소화 유지

② 인증과 권한 모듈

역할
구글 로그인 기반 학생/교사 권한 분리
입력
구글 로그인 정보(OAuth 토큰)
출력
역할 기반 접근 제어 결과
예외
등록되지 않은 교사 계정 로그인 시 접근 거부
주의
권한 검사는 반드시 서버(또는 DB 보안 규칙)에서 수행

③ 데이터 모델 모듈

역할
학생·교사·미션 설정·인증 기록·판정 결과·펫 상태 저장
입력
사용자/설정/판정 결과
출력
화면에 필요한 요약 데이터
예외
중복 제출, 동시 저장 충돌
주의
개인정보 최소 수집 원칙 준수

④ 입력/업로드 처리 모듈 변경

역할
사진 업로드(카메라 즉시 촬영 또는 사진첩에서 선택), 파일 크기/형식 검증
입력
사진 파일(촬영본 또는 갤러리 기존 파일)
출력
업로드 결과(저장 경로/식별자)
예외
형식 불가, 용량 초과, 업로드 실패 시 재시도 안내
주의
사진첩 선택은 실시간 촬영이 아니므로 오래되거나 무관한 사진이 제출될 수 있음. 이번 범위에서는 별도 검증 없이 자기 점검 취지의 안내 문구로 대응하고, 촬영시각(EXIF) 검증은 구조만 열어둔 확장 항목으로 둠

⑤ 판정 로직 모듈

역할
세 끼 판정, 잔반 제로 판정, 고난도 판정, 경험치 계산
입력
사진(또는 AI 판정 점수), 미션 설정
출력
성공/실패, 경험치 변화, 펫 성장 업데이트
예외
AI 판정 실패/지연 시 기본 규칙으로 대체 판정
주의
교사 설정값의 적용 시점(버전)을 명확히 구분

⑥ 펫 성장/경험치 모듈

역할
경험치 누적, 레벨/단계 계산, 성장 상태 생성
입력
경험치 변화(expDelta)
출력
펫 성장 상태(PetState)
예외
동시 다발 제출로 인한 경험치 이중 반영 방지
주의
같은 입력이면 같은 결과가 나오도록 결정론적으로 계산

⑦ 기록 요약/대시보드 모듈

역할
학생별 요약(오늘 진행, 누적 경험치, 최근 판정) 집계
입력
인증 기록/판정 결과
출력
대시보드용 집계 데이터
예외
기록이 없는 학생은 "기록 없음"으로 표시
주의
학생 수가 늘어도 목록 로딩 성능 유지(페이지네이션 고려)

⑧ 개인정보보호 구현 모듈

역할
개인정보 최소 수집, 저장/삭제, 접근 통제, 로그 관리
입력
학생 식별 정보, 기록
출력
보호된 데이터 처리 결과
예외
삭제 요청 시 관련 인증 기록까지 함께 처리
주의
학생 이름/학번은 필요한 범위에서만 저장, 로그에는 남기지 않음

⑨ 정책 문서 생성 모듈

역할
개인정보 처리방침·이용약관·서비스 설명서 초안 생성
입력
기관명, 담당자 정보, 시행일
출력
푸터 게시용 문서 초안
예외
기관 정보 미입력 시 자리표시 문구로 대체
주의
실제 법률 문구 확정이 아닌 "검토용 초안"임을 표시

⑩ 테스트 모듈

역할
기능별 테스트 시나리오 생성 및 검증
입력
테스트 케이스(가짜 데이터)
출력
테스트 결과(통과/실패)
예외
실패 시 원인 모듈을 특정해 로그로 남김
주의
실제 학생 데이터가 아닌 가짜 데이터로만 테스트

권한 설계

  • 학생은 자기 기록만 조회 · 제출할 수 있다
  • 교사는 자기 담당 학생의 기록만 조회할 수 있다
  • 미션 설정 수정은 교사만 할 수 있다
  • 모든 권한 검사는 서버(또는 데이터베이스 보안 규칙)에서 강제한다 — 화면에서 메뉴를 숨기는 방식만으로는 허용하지 않는다

개인정보 보호 구현 계획

전제 이름 · 학번처럼 학생을 특정할 수 있는 정보를 다룹니다. 최소 수집 원칙을 적용하고, 기록은 "다음에 다시 열어도 남아 있어야" 하므로 영구 저장 또는 보유기간 정책에 따라 저장합니다.
  • 접근 통제 — 학생은 본인 기록만, 교사는 담당 학생만 조회
  • 최소 수집 · 가명 옵션 — 이름 대신 번호나 닉네임을 표시 이름으로 선택할 수 있는 설정 제공
  • 전송/저장 보호 — 업로드 사진과 기록은 안전한 저장소에 저장, 전송 구간은 HTTPS로 암호화
  • 로그 관리 — 학번 전체 등 민감정보를 서버 로그에 그대로 남기지 않음
  • 삭제 · 정정 — 교사 또는 운영 정책에 따라 계정/기록 삭제·정정 기능 또는 절차 안내 제공
  • 보유 기간 — 학기/학년 단위 보관 후 파기, 교사 대시보드에서 조기 삭제 요청 가능

학습지원 소프트웨어 심의 대응을 위해, 서비스 사용 목적을 교사가 화면에서 직접 확인·설정합니다.

  • 비밀번호 저장 로직을 직접 만들지 않고 구글 로그인(관리형 인증)만 사용

테스트 기준 · 완료 기준

테스트 시나리오

  • 끼니/전후 선택 후 사진 업로드(촬영 또는 사진첩) → 결과 화면이 즉시 표시된다
  • 사진 형식 불가 · 용량 초과 시 안내 후 재시도할 수 있다
  • 같은 설정 · 같은 점수 입력이면 판정 결과가 항상 동일하다
  • 교사가 규칙을 저장하면 다음 인증부터 변경 사항이 반영된다
  • 학생은 다른 학생의 기록에 접근할 수 없다
  • 교사는 자기 담당 학생의 기록만 접근할 수 있다
  • 서버 로그에 민감정보(학번 전체 등)가 그대로 노출되지 않는다

완료 기준

  • 학생 인증 화면 + 즉시 결과 화면(성공/실패, 경험치/펫 성장, 오늘 기록)
  • 일일 세 끼 판정 + 전/후 잔반 제로 판정 + 고난도 보너스 연계
  • 교사 대시보드(학생 현황) + 규칙/보너스/고난도 조건 수정 및 저장 후 반영
  • 개인정보 처리방침 초안 + 이용약관 초안 + 푸터 링크 포함
  • 위 테스트 시나리오 통과

15

참고 안내

AI 판정의 한계 초기 버전의 AI 판정은 완벽하지 않을 수 있습니다. 학생·교사 화면과 업로드 안내에 "판정 결과는 미션 수행을 돕기 위한 참고이며, 사진을 잘못 인식할 수 있습니다"라는 문구를 함께 표시합니다.
사진첩 선택과 자기 점검 취지 사진첩에서 고른 사진이 실제 오늘 식사가 아닐 가능성은 이번 범위에서 기술로 막지 않습니다. "오늘 먹은 식사 사진을 올려주세요"라는 안내 문구와 학급 지도로 보완하며, 필요해지면 촬영시각 검증 등을 이후 단계에서 추가할 수 있도록 구조만 열어둡니다.
개발 순서 가장 단순하게 동작하는 버전부터 만들고, 판정 정확도와 기능 확장은 이후 단계에서 점진적으로 개선합니다.
